# CareSlot — a complete nexus v4 example

A clinic appointment system, taken through every v4 step: business requirements → product
requirements → architecture → designs → dev tasks → a change request. **CareSlot and everything in
it is made up**; it exists to show what each step produces and how the pieces trace to each other.

Read it in order with [WALKTHROUGH.md](WALKTHROUGH.md), or jump to a file:

| Step | Who | Command | Files |
|---|---|---|---|
| 1. Business requirements | Product owner / BA | `/brd` | [docs/requirements/BRD.md](docs/requirements/BRD.md) — BR-001 … BR-006 |
| 2. Product requirements | Product owner / BA | `/prd` | [docs/requirements/PRD.md](docs/requirements/PRD.md) — US-001 … US-008, FR-, NFR-, AC- |
| 3. Architecture and epics | Architect | `/architect careslot` | [docs/arch-docs/careslot/](docs/arch-docs/careslot/) — 9-section doc + one ADR file per epic (E001 Booking, E002 Schedule, E003 Notifications) |
| 4. Design (optional command) | Designer | `/design careslot --system docs/designs/design-system`, or copy a Claude Design / Figma Make export | [docs/designs/careslot/](docs/designs/careslot/) — 4 frames, tokens, a React export, `design.json`; the design system in [docs/designs/design-system/](docs/designs/design-system/) |
| 5. Project scaffold (Day 0) | Tech lead | `/scaffold` | the codebase skeleton at the repo root — `careslot/`, the five apps, templates per screen, theme, Docker, CI, `AGENTS.md` |

## What this example shows

- **Requirements are product-wide; epics come from the architecture.** One BRD and one PRD; the architect
  splits the product into three epics, and designs and dev tasks follow them.

- **One chain of IDs from business to code.** `BR-004` (remind every patient) → `US-006` → `FR-NOTIF-001`
  → architecture §4 Background jobs (Celery) → screen `DES-003` → task `NOTIF-002`.
- **The stack decides, not the design tool.** The designer exported React components, but the
  architecture chose Django + htmx (ADR-CARESLOT-E001-001), so screens are built from the
  HTML frames and tokens; the React export is only a behaviour reference.
- **A change request touches only what it should.** CR-001 changed `FR-NOTIF-001` and `US-005` and added
  `FR-BOOK-004` and `AC-015`; of the tasks, two were re-planned (`BOOK-005`, `NOTIF-002`), one was added for
  the new requirement (`BOOK-006`), and the other nine weren't touched.
- **nexus's own checks pass** on every file here — the repository's tests run them on each change.

## Try it

To **build** CareSlot yourselves as a team — product owner, architect, designer, tech lead, developers, each
with their own role — follow the team training (https://v4-preview.nexus-coderstudio.pages.dev/training) with the client pack in
[`../careslot-client-pack/`](../careslot-client-pack/). This folder is what a finished run looks like.

To explore this finished copy instead:

```bash
alias nexus4="uvx --refresh --from 'git+https://github.com/rcdelacruz/nexus-dev-toolkit@v4-preview' nexus"   # the nexus 4 preview; your nexus 3 stays as it is
cp -r examples/clinic-appointments ~/careslot && cd ~/careslot && git init -q && git add -A && git commit -qm "start"
nexus4 init . --role product                       # or architect / designer / developer
export TYPESAFE_API_KEY=<your key>                 # optional: TypeSafe judgments; without it, nexus's built-in rules
```

Then open Claude Code in `~/careslot` and follow the exercise at the end of the walkthrough.

## Generated vs written by hand

Written by hand (as a product owner, architect, designer and tech lead would): the BRD, PRD, architecture doc and
ADRs, design frames, tokens and export, the Day 0 scaffold, and the task rows. The scaffold's migrations and
lock files come from Django, uv and npm. Generated by nexus's own tools — never edit
them by hand; run `python3 scripts/build_example.py` from the nexus repository:
`design.json`, the `TRACE_IDS` column, `CR-001.json`, and the guides/templates in `docs/`.
