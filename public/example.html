nexus v4 — preview (pre-release)

Example: CareSlot, a Clinic Appointment System

One small product taken through every nexus v4 step, with every file it produces — so product owners, architects, designers and developers can see what "done" looks like at each step and how a change request finds exactly the right tasks. CareSlot is made up.

Preview. nexus v4 isn't on PyPI yet. This page runs it as nexus4, next to your nexus 3, which stays exactly as it is. Set it up with one line: Try It.

What It Is

Three outpatient clinics want online booking: patients book, see and cancel appointments, receptionists manage the day, and everyone gets a reminder. The folder examples/clinic-appointments holds the whole docs/ tree; its WALKTHROUGH.md goes role by role. The BRD and PRD cover the whole product; the architecture splits it into three epics — Booking, Schedule, Notifications — and the designs and dev tasks follow them.

Because every document cites the IDs before it, a change to BR-004 or FR-NOTIF-001 can be followed to the exact screen and task it affects.

Step by Step

Product owner — /brd, /prd

One BRD and one PRD for the whole product, in docs/requirements/. The BRD comes from kickoff notes plus one round of questions; anything nobody could answer stays an Open Question with an owner. The PRD's plan shows every business rule served:

BR-002 → US-003, FR-BOOK-002          BR-004 → US-006, FR-NOTIF-001, NFR-003
BR-003 → US-003, US-007, US-008, FR-BOOK-003, FR-SCHED-001, FR-SCHED-002

Architect — /architect careslot

status: ok   sections: 9/9   stack (Choice lines): Django, Python, htmx, Tailwind CSS,
PostgreSQL, Celery, Redis, Docker, AWS   ADRs: 3
epics: E001 Booking        US-002 US-003 US-004 US-005 FR-BOOK-001…004
       E002 Schedule       US-001 US-007 US-008 FR-AUTH-001 FR-SCHED-001 FR-SCHED-002
       E003 Notifications  US-006 FR-NOTIF-001

The designer also exported React; the architecture mentions it only as a reference, so React is not in the stack and screens are built from the HTML frames.

Designer — /design careslot --system docs/designs/design-system (optional)

Tech lead — /scaffold (Day 0, once)

Runs once on the approved docs, before any task is planned: stack from the Choice lines, exact versions from resolve_package_versions, the theme from the tokens, one template per screen from the HTML frames (not from the React export — the stack is Django), AGENTS.md, and a passing build gate.

Tech lead — /dev-tasks-planner careslot (one CSV per epic); developers — /evaluate, /plan, /apply, /validate

BOOK-004  Double-booking constraint   TRACE_IDS: US-003, FR-BOOK-003, ADR-…-E001-002, AC-007
NOTIF-002 SMS reminder                TRACE_IDS: US-006, FR-NOTIF-001, AC-011, NFR-003

The Change Request

The clinic asks for the reminder 2 hours before (not 24) and a required cancellation reason. Requirements, architecture and the My Appointments frame are updated first; then nexus reads the git diff:

CR-001  Changed: FR-NOTIF-001, US-005    Added: AC-015, FR-BOOK-004    Removed: —
Affected tasks: BOOK-005, NOTIF-002 → re-planned · BOOK-006 added · 9 others untouched

Lines that only mention an ID don't count — the new FR-BOOK-004 row says "serves BR-005", but BR-005 didn't change, so nothing tracing to BR-005 is touched.

Try It

To build CareSlot yourselves, as a team with real roles, use the team training. Or explore the finished project:

$ alias nexus4="uvx --refresh --from 'git+https://github.com/rcdelacruz/nexus-dev-toolkit@v4-preview' nexus"   # the nexus 4 preview
$ cp -r examples/clinic-appointments ~/careslot && cd ~/careslot && git init -q && git add -A && git commit -qm "chore: start"
$ nexus4 init . --role product

nexus4 is the preview under its own name: your nexus (nexus 3) and your other projects stay as they are, and every run picks up the newest preview by itself. To keep nexus4 in new terminals, add the alias line to ~/.zshrc (or ~/.bashrc).

$ export TYPESAFE_API_KEY=<your key>   # optional: TypeSafe judgments

Optional — TypeSafe. With a key, nexus asks TypeSafe where it would otherwise guess from keywords: the sections of a doc that doesn't follow the guide, design tokens its rules can't place, and which technologies a doc really uses. Without a key, nexus uses its built-in rules and nothing is sent. Add the line to ~/.zshrc (or ~/.bashrc) and start Claude Code from that terminal. Never put the key in .mcp.json: it's shared in git.

Then rehearse CR-002 from the walkthrough: allow 3 future appointments instead of 2. The record should list AC-006, BR-002, FR-BOOK-002 and US-003 as changed, and the planner should re-plan BOOK-003, BOOK-004 and the booking epic row — nothing else.
