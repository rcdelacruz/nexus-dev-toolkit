nexus v4 — preview (pre-release)

nexus for Designers

You design; developers build it in whatever stack the architect chose. Three ways to hand over, all checked against your team's design guide and the requirements:

You work inThen
Claude Code, with your own design system/design <app> --system <design system> creates every screen, epic by epic, from your tokens and components only
Claude Design (Claude Desktop), Figma Make or another toolCopy the exported files into docs/designs/<app>/ and commit — no command needed; the tech lead's /scaffold reads them and runs the same checks
An export you want reviewed first/design <app> <export> tells you in plain words what to fix, per screen

/design is optional. Screens follow the architect's epics (docs/arch-docs/<app>/, the Epic: line of each ADR file).

Preview. nexus v4 isn't on PyPI yet. This page runs it as nexus4, next to your nexus 3, which stays exactly as it is. Set it up with one line: Set Up Once.

Who This Is For

Product and UI designers who export from Figma, Figma Make, Claude Design or similar. You work only in docs/designs/; nexus does the git steps (branch, commit, pull request). New to git? Start with the git guide.

Set Up Once

$ alias nexus4="uvx --refresh --from 'git+https://github.com/rcdelacruz/nexus-dev-toolkit@v4-preview' nexus"   # the nexus 4 preview
$ nexus4 init . --role designer   # installs /design and /change-request only

nexus4 is the preview under its own name: your nexus (nexus 3) and your other projects stay as they are, and every run picks up the newest preview by itself. To keep nexus4 in new terminals, add the alias line to ~/.zshrc (or ~/.bashrc).

What to Export

One folder or .zip per app, in docs/designs/<app>/, with:

PartWhy
HTML frames — one per screen, e.g. Frame - Login.dc.htmlThe visual truth for every stack, React or not
Tokens — a CSS file with colour roles as variables (--background, --foreground, --primary, …), light and darkDevelopers turn them into the app's theme; frames are checked against them
react-export/ (optional) — Figma Make, Claude Design export, a Next.js or Vite projectReused as code only when the app is React
assets/Images and icons the frames use

Leave out node_modules/, .next/, dist/ and build/ — they're generated, often hundreds of MB, and nexus skips them anyway.

/design <app> [--system path | export path]

Create (--system): give it your design system — a tokens file, your components and rules, or a Claude Design design-system export. It plans one screen per story, by epic, using only what the system has (a missing colour or component is a question for you, never invented), then writes the HTML frames, tokens.css and design.json; the system itself is kept in docs/designs/design-system/.

Review (an export path, or nothing): nexus reads every file by its content (not its name): frames become screens with stable IDs (DES-001, DES-002 … — a screen keeps its ID when you re-export), frames are paired with matching export components, and every colour in a frame is compared with your tokens. The plan shows you:

DES-001  Login        Frame - Login.dc.html   → LoginScreen.jsx   states: error
DES-002  Orders       Frame - Orders.dc.html  → OrdersPage.jsx    states: empty, loading
Coverage: US-001 → Login · FR-ORD-001 → Orders · US-007 → no screen
To fix:   Login uses #6b6f6b, which isn't a token — use --muted, or add it to the tokens

You confirm the screen list and which requirements each screen covers. Nothing is written before you say go.

What nexus Checks

RuleSeverityWhat it means
D1BLOCKERA tokens file exists with background, foreground and primary colours
D2BLOCKEREvery requirement with a UI part has a screen
D3FIX NOWOne HTML frame per screen
D4FIX NOWColours in frames come from the tokens
D5FIX NOWScreens show their empty / loading / error / disabled states
D6FIX NOWMobile and desktop frames when the requirements ask for both
D7BACKLOGEach frame has a matching component in the export, when there is one
D8BACKLOGAssets live in assets/

Your team can change these in docs/designs/DESIGN-GUIDE.md — nexus writes it once and never overwrites it. These checks catch, before handoff, the questions developers otherwise ask afterwards: which breakpoints, what an empty table says, what happens while a button waits.

Any Stack, Not Just React

The architect decides the app's stack. If it's React or Next.js, developers may reuse your export's components. For anything else — Vue, Angular, Go with htmx, Flutter, SwiftUI — they build each screen from your HTML frame and tokens, and use the export only to understand behaviour. That's why frames and tokens matter even when you also export React.

Change Requests

When a change request touches your screens, the architect lists which ones. Update the design, re-export, and copy it in again (or run /design again): screens keep their IDs, so developers see exactly which screens changed.
