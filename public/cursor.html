Guide — no install required

EPAV in Cursor

nexus ships its workflow as Claude Code skills, but the method behind it — Evaluate → Plan → Apply → Validate — is tool-agnostic. This guide gives Cursor users the principles, how they map onto Cursor's own features, and an optional one-file setup for the nexus MCP tools.

Why a Guide, Not a Plugin

Cursor already has the building blocks EPAV needs: Plan Mode with an approval step, project rules, native AGENTS.md support, and MCP. What it doesn't enforce is the discipline — orient before planning, never code without an approved plan, stay in scope, and don't call it done without evidence. That discipline is the valuable part of nexus, and it fits in one rule file.

Using Claude Code? You don't need this page — nexus init installs everything. See the docs.

The EPAV Principles

One task at a time, four steps, one human gate. Each step has a single job and a clear exit.

EVALUATE → PLAN → [human approves] → APPLY → VALIDATE

1. Evaluate — orient before deciding anything

  • Read before you write. Load the task's user story and acceptance criteria, the project's coding standards (AGENTS.md), the relevant architecture section, and any prior patterns in knowledge/.
  • Find the blast radius. Which files, modules and high-traffic code does this touch? What must already exist?
  • Output a short summary, nothing else. Task, touches, depends on, constraints, risk. No plan, no code.

2. Plan — a blueprint a human approves

  • Numbered steps, file by file, each saying what changes and why.
  • List files created, modified, deleted and what else references them.
  • State the constraints that apply — coding standards, architecture decisions, acceptance criteria.
  • Stop and wait. No code until a human explicitly approves. This gate is the contract every later step is bound by.

3. Apply — implement exactly the plan

  • Follow the steps in order. No extra features, no unrelated refactors.
  • Scope changes stop the work. If something unexpected requires a different plan, say "Discovered: X — outside the plan. Revise?" and wait.
  • Report what was created, modified and deliberately skipped.

4. Validate — done means proven, not claimed

  • Run the real checks: build, tests, type check — they must pass.
  • Mark every acceptance criterion PASS / FAIL / PARTIAL with evidence.
  • Classify issues: [BLOCKER] and [FIX NOW] are fixed before moving on; [BACKLOG] goes to knowledge/retros/.
  • Feed it back. A non-obvious lesson becomes a note in knowledge/patterns/ so the next Evaluate starts smarter.

The EPAV Rule

Save this as .cursor/rules/epav.mdc and commit it. alwaysApply: true puts it in every Agent session, so the whole team works the same way.

---
description: EPAV workflow — evaluate, plan, apply, validate
alwaysApply: true
---

# EPAV workflow

Work one task at a time through four steps. Never skip the gate.

1. EVALUATE — Before planning, read the task and its acceptance
   criteria, AGENTS.md, the relevant architecture doc, and
   knowledge/. Output only:
   Task / Touches / Depends on / Constraints / Risk.

2. PLAN — Numbered steps, file by file, with what changes and why.
   List files created/modified/deleted and what references them.
   Then STOP. Write no code until the user explicitly approves
   (in Plan Mode, clicking build is the approval).

3. APPLY — Implement exactly the approved steps, in order. No extra
   features or unrelated refactors. If the plan turns out wrong,
   stop and say "Discovered: X — outside the plan. Revise?"

4. VALIDATE — Run build, tests and type check; they must pass. Mark
   each acceptance criterion PASS / FAIL / PARTIAL with evidence.
   Fix [BLOCKER] and [FIX NOW] issues before finishing; log
   [BACKLOG] items to knowledge/retros/. Never claim done without
   evidence.

Extra work found along the way goes to knowledge/retros/, not into
the current task.

Copy-Paste Prompts

With the rule in place, these are all you need. Paste into Agent chat.

Evaluate (Plan Mode)

Evaluate this task — do not plan or write code yet:
<task description, or path to the task CSV row>
Output the EVALUATE summary only.

Plan (Plan Mode)

Write the EPAV plan for this task: numbered steps, files
created/modified/deleted, blast radius, constraints. Then stop.

Apply (after you approve the plan)

Build the approved plan exactly. Stop and ask if anything
needs to go outside it.

Validate (Agent)

Validate: run the build and tests, mark every acceptance
criterion PASS/FAIL/PARTIAL with evidence, fix all BLOCKER and
FIX NOW issues, and log BACKLOG items to knowledge/retros/.
Want /evaluate-style slash commands? Cursor turns any skill into one: put the prompt in .cursor/skills/evaluate/SKILL.md with name: evaluate and a description in its frontmatter (the folder name must match name). Add disable-model-invocation: true so it only runs when you type /evaluate, never on Agent's own initiative.

Optional: the nexus MCP Tools

The nexus MCP server works in Cursor unchanged. Requires uv. Create .cursor/mcp.json:

{
  "mcpServers": {
    "nexus": {
      "type": "stdio",
      "command": "uvx",
      "args": ["--refresh", "--from", "nexus-dev-toolkit", "nexus-mcp"]
    }
  }
}

Make sure the nexus server is toggled on under Customize in the sidebar. By default Agent asks your approval before each MCP tool call. Agent can then call:

ToolEPAV stepWhat it does
load_taskEvaluateLoads a task row (user story, description, acceptance criteria, dependencies) from a CSV, with a knowledge-graph query on it if one is built.
ingest_architecture_docEvaluateExtracts stack, data model, auth, error format, security rules and ADRs from an architecture doc.
generate_project_rulesSetupWrites AGENTS.md and the knowledge/ structure from an architecture doc. Cursor reads AGENTS.md automatically.
resolve_package_versionsApplyResolves exact pinned versions with the real package manager in a temp dir, so manifests are deterministic.

Optional: Knowledge Graph Hook

If you use graphify, keep the graph current after every Agent edit with .cursor/hooks.json:

{
  "version": 1,
  "hooks": {
    "afterFileEdit": [
      { "command": "graphify update . --force 2>/dev/null || true" }
    ]
  }
}

Hooks only run in trusted workspaces, and afterFileEdit fires on Agent edits only — Tab completions don't trigger it. codegraph syncs itself and needs no hook.

What You Don't Get vs. Claude Code

  • No nexus init / nexus sync. The rule and prompts above are yours to maintain; check this page after nexus releases.
  • No built-in skills or reviewer agents. /code-review, /pr-review and the specialist reviewers are built and tested for Claude Code only. (Cursor does load subagents from .claude/agents/, but the nexus reviewers rely on Claude Code-only tools and aren't supported there.)
  • No enforced orchestrator. /epav chains the steps with a hard gate in Claude Code; in Cursor, Plan Mode's review step plays that role.
