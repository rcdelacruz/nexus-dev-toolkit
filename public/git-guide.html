Git for Architects and Designers

Requirements, architecture and designs live in the same repository as the code, in docs/. That's what lets a change request reach exactly the right developer tasks. You need only a handful of git steps — and the nexus commands run most of them for you.

Preview. nexus v4 isn't on PyPI yet. This page runs it as nexus4, next to your nexus 3, which stays exactly as it is. Set it up with one line: alias nexus4="uvx --refresh --from 'git+https://github.com/rcdelacruz/nexus-dev-toolkit@v4-preview' nexus".

Why Git

  • One source of truth. Developers build from the same files you edit — no copying from Google Docs or Figma links that drift.
  • Every change is recorded. Git shows exactly which lines of a requirement or design changed, and nexus turns that into "these requirement IDs changed → these tasks need re-planning".
  • Reviews before anything lands. Your changes go through a pull request your team approves.

One-Time Setup

# git and the GitHub command-line tool (macOS shown; Windows: install Git for Windows and GitHub CLI)
$ brew install git gh
$ gh auth login                       # sign in to GitHub once
$ gh repo clone <org>/<project>       # your copy of the project
$ cd <project> && nexus4 init . --role designer   # or --role architect

Prefer clicking? GitHub Desktop does the same steps with buttons; the nexus commands still open pull requests for you.

Reviews

Who approves what is set in .github/CODEOWNERS: architects approve docs/arch-docs/, designers docs/designs/, product docs/requirements/, developers everything else. nexus writes a template to .github/CODEOWNERS.nexus-template; replace the placeholder team names with your real GitHub teams, then rename it to CODEOWNERS.

Undo a Mistake

SituationCommand
Throw away edits to one file you haven't committedgit restore docs/designs/core/tokens.css
See what you changedgit status and git diff
Start over from the latest maingit switch main && git pull (your branch stays saved)
A pull request you no longer wantClose it on GitHub — nothing reaches main

Three Rules

  • Only docs/. If a command or a diff shows anything outside docs/, stop and ask a developer.
  • Never push to main directly. Always through a pull request.
  • Pull before you start. Most conflicts come from working on an old copy.
